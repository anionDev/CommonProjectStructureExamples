# AngularCodeUnit

## Purpose

`AngularCodeUnit` is the demonstration-codeunit for an Angular-web-application. It shows which shape such a codeunit has in a repository which implements the CommonProjectStructure, not a realistic application: the only page it serves is a user-settings-page, which exists so that there is something to build, to test and to take a screenshot of.

Two things about it are worth looking at when a comparable codeunit is created:

- **It consumes the API of another codeunit of the same repository.** `DotNetWebAPICodeUnit` is declared in `dependentcodeunits`, its API-specification is taken from `Other/Resources/DependentCodeUnits`, and the client in `src/app/generated` is generated from it. That folder is therefore never edited by hand; it is regenerated by `npm run generate-api-client` and by the build.
- **It is translatable.** The texts of the templates are marked with `i18n`-attributes, and the supported languages are declared in `Other/CommonTasks.py`. The build extracts the texts into `Other/Resources/Translations/messages.xlf` (`npm run extract-translations`), creates one `messages.<language>.xlf` per language (initially with the english texts), builds one application per language (`ng build --localize`) and adds an `index.html` which forwards to the language of the browser. The xlf-files are maintained by a translation-service and not by hand.
- **It has visual-regression-tests.** They open the page in chromium, firefox and webkit, once in the light and once in the dark color-scheme, and compare a screenshot with the corresponding baseline in `Other/Resources/VisualRegressionBaselines`.

## Build and test

The codeunit is built and tested by the scripts of the CommonProjectStructure, so it is built by the pipeline of the repository (`task bb` in the repository-root) and not by calling the Angular-CLI directly. The scripts are `Other/Build/Build.py`, `Other/QualityCheck/Linting.py` and `Other/QualityCheck/RunTestcases.py`.

The npm-scripts behind them exist per target-environment (`Development`, `QualityCheck`, `Productive`):

- `npm run build-<target-environment>` builds the application.
- `npm run test-<target-environment>` runs the unit-tests (executed by vitest in jsdom) including the coverage-measurement.
- `npm run lint` runs the linting.
- `npm run generate-api-client` regenerates the client for `DotNetWebAPICodeUnit`.

The end-to-end- and visual-regression-tests are defined in `e2e` and are configured in `playwright.config.ts`.

## Run locally

Run `npm start` to serve the application at `http://localhost:4200`. That command starts the Angular-development-server with the proxy-configuration `DevelopmentProxy.config.json`, which forwards the API-requests of the page to a locally running instance of `DotNetWebAPICodeUnit`.

## Update the baseline-screenshots

After an intended change of the appearance of a page the baseline-screenshots are regenerated with `task UpdateVisualRegressionBaselines` (or shorter: `task uvrb`) in the repository-root. The regenerated screenshots have to be reviewed before they are committed, because that command accepts every change of the appearance as the new expected state.
